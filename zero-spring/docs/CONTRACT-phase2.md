## 4. identity — servis & endpoint sözleşmesi

### 4.1 Role (`identity/role/RoleService.java`, `web/RoleController.java`)
- `GET /api/roles` (perm `roles.read`, Pageable) → `Page<RoleDto>`
- `GET /api/roles/{id}` (`roles.read`) → `RoleDetailDto` (permissions dahil)
- `POST /api/roles` (`roles.create`) body `CreateRoleRequest(name @NotBlank, displayName @NotBlank, permissions Set<String>, isDefault)` → 201 `RoleDetailDto`. Tenant scope: `tenantId = CurrentUser.tenantId()`. HOST-ONLY izin tenant rolüne atanamaz → `DomainException(VALIDATION)`.
- `PUT /api/roles/{id}` (`roles.update`) `UpdateRoleRequest(displayName, permissions, isDefault)`; static rol adı değişmez.
- `DELETE /api/roles/{id}` (`roles.delete`); static rol silinemez → `DomainException(VALIDATION)`; role kullanıcıya atalıysa 409.
- `POST /api/roles/{id}/clone` (`roles.create`) → yeni rol (aynı izinler, adı `{name}_copy`).
- DTO: `RoleDto(id, name, displayName, isStatic, isDefault, memberCount)`, `RoleDetailDto(id, name, displayName, isStatic, isDefault, Set<String> permissions)`.

### 4.2 User genişletme (`identity/user/UserService.java`, `web/UserController.java`)
Mevcut CRUD KORUNUR; eklenenler:
- `POST /api/users/{id}/unlock` (`users.unlock`) → failedLoginAttempts=0, lockoutEndAt=null.
- `PUT /api/users/{id}/roles` (`users.update`) `AssignRolesRequest(Set<String> roleNames)`.
- `PUT /api/users/{id}/organization-units` (`users.update`) `AssignOuRequest(Set<Long> ouIds)`.
- `POST /api/users/{id}/activate` / `/deactivate` (`users.update`) → aktif; deaktivasyonda `RefreshTokenRepository.revokeAllByUserId`.
- `DELETE /api/users/{id}` → **soft delete** (deleted=true, deleted_at=now); `@SQLRestriction("deleted = false")` User'a eklenir.
- `GET /api/users/export` (`users.read`) → Apache POI xlsx (`ResponseEntity<byte[]>`, content-type openxml).
- CreateUserRequest genişler: `name, surname, phoneNumber` (opsiyonel), `organizationUnitIds Set<Long>` (opsiyonel).
- UserDto genişler: `name, surname, phoneNumber, emailConfirmed, lockoutEndAt`.
- Duplicate username (aynı tenant) → 409 `DomainException(CONFLICT)`.

### 4.3 Profil (`identity/user/ProfileService.java`, `web/ProfileController.java`)
- `GET /api/profile` (authenticated) → `ProfileDto`.
- `PUT /api/profile` → `UpdateProfileRequest(name, surname, phoneNumber, email)`; e-posta değişince emailConfirmed=false + doğrulama e-postası.
- `POST /api/profile/change-password` `ChangePasswordRequest(currentPassword, newPassword)` → politika + history kontrolü.

### 4.4 Şifre politikası (`identity/password/`)
- `PasswordPolicy` setting'ten okunur (bkz §6 setting adları). `PasswordPolicyValidator` (Passay) `validate(String)`.
- `PasswordHistory` entity + repo; `checkNotRecentlyUsed(userId, rawPassword, N)`; şifre değişince eski hash history'ye yazılır (son N tutulur, N = setting `App.Password.HistoryCount` default 3).
- Login sonrası `shouldChangePassword` true ise `/api/auth/me` bunu bildirir (flag), zorlama frontend'te.

### 4.5 Organization Units (`identity/ou/OrganizationUnitService.java`, `web/OrganizationUnitController.java`)
- Materialized path `code` (5 hane zero-padded, nokta ayraç: root `00001`, çocuk `00001.00001`). ABP paritesi.
- `GET /api/organization-units` (`organizationunits.manage`) → ağaç (`List<OuDto>` parent_id ile) tenant-scoped.
- `POST` `CreateOuRequest(displayName, parentId)` → code hesaplanır (son kardeş +1).
- `PUT /api/organization-units/{id}` `UpdateOuRequest(displayName)`.
- `PUT /api/organization-units/{id}/move` `MoveOuRequest(newParentId)` → alt ağacın code'ları toplu güncellenir (tek tx).
- `DELETE /api/organization-units/{id}` → alt ağaç + user atamaları temizlenir.
- `OuDto(id, parentId, code, displayName, memberCount)`.

### 4.6 Impersonation (`identity/auth/ImpersonationService.java`, AuthController'a ekleme)
- `POST /api/auth/impersonate` (`users.impersonate`) `ImpersonateRequest(Long targetUserId, Long targetTenantId)`:
  host→tenant kullanıcı veya aynı tenant. Tek kullanımlık token (Redis/cache, 30sn TTL) üretir → `{ impersonationToken }`.
- `POST /api/auth/impersonate/authenticate` `ImpersonateAuthRequest(String impersonationToken)` → hedef kullanıcı için access+refresh; JWT'ye `act` (actor) claim = gerçek userId + `actTenant`.
- `POST /api/auth/back-to-impersonator` → `act` claim'den gerçek kullanıcıya döner (yeni token çifti).
- Audit: impersonation login `audit_logs`'a `service_name=Impersonation` ile yazılır (actor görünür).
- Cascade impersonation yasak (act claim zaten varsa 403).
