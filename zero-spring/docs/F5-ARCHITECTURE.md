# C) F5 Architecture Addendum — SaaS ticari katman

Girdi: `F5-SAAS-INVENTORY.md`, `F5-GAP-ANALYSIS.md`. Mevcut mimari kararlar (ADR-0001..0008) korunur.
Bu belge yalnız SaaS katmanının Spring tarafındaki sınırlarını ve stratejilerini tanımlar.

---

## 1. Domain sınırları (Modulith)

Yeni tek top-level modül: **`saas`**.

```
com.mycompanyname.zero.saas
├─ package-info.java        @ApplicationModule(allowedDependencies = {"shared", "tenancy", "settings"})
├─ api/                     @NamedInterface("api")   ← dışa açık YÜZEY (tüketiciler yalnız bunu görür)
│   ├─ FeatureChecker.java      boolean isEnabled(String), String value(String), int intValue(String)
│   ├─ SubscriptionGuard.java   boolean isTenantSubscriptionValid(Long tenantId)
│   └─ SaasFeatures.java        feature adı sabitleri
├─ edition/                 Edition, EditionFeature, EditionRepository, EditionService, web/
├─ feature/                 FeatureDefinition(+s registry), TenantFeature, FeatureValueResolver, RequiresFeature(AOP)
├─ subscription/            Subscription (agregat kök), SubscriptionStatus, SubscriptionService, web/
├─ billing/                 BillingProvider (SPI), ManualBillingProvider, PaymentIntent/Payment, Invoice (C)
└─ webhook/                 WebhookEvent (idempotency store), WebhookController (C)
```

### 1.1 Bağımlılık yönü (döngü yasağı — F5-R1)

```
identity ──(saas :: api)──▶ saas        // feature gating, abonelik kapısı
saas ──▶ {shared, tenancy, settings}    // Tenant entity, ayarlar
tenancy ──▶ shared                      // DEĞİŞMEZ: tenancy yaprak kalır
```

**Kurallar:**
1. `saas` çekirdeği **`identity`'ye bağlanmaz**. SaaS izin sabitleri `saas` içinde tanımlanır (`SaasPermissions`), permission ağacına kayıt **`config`/`seed`** (OPEN modüller) üzerinden yapılır.
2. `tenancy`'ye `saas` bağımlılığı **eklenmez**. Tenant silinince abonelik temizliği **Modulith application event** ile (`TenantDeactivated`/`TenantDeleted` → `@ApplicationModuleListener` in `saas`).
3. `identity`'nin `allowedDependencies`'ine `"saas :: api"` eklenir (mevcut `"notification :: email"` ile birebir aynı desen).
4. `ModularityTests` bu kuralları derleme/test zamanında zorlar — ihlal build'i kırar.

## 2. Veri modeli (V4 taslağı)

Konvansiyon: `bigint generated by default as identity`, `timestamptz`, `tenant_id bigint references tenants(id)` nullable,
`unique nulls not distinct`, `ix_`/`uq_` adlandırma, enum'lar `varchar` + check yorumu.

```
editions                    id, name UQ, display_name, description,
                            monthly_price numeric(19,4), annual_price numeric(19,4), currency varchar(3),
                            trial_day_count int, grace_day_count int, expiring_edition_id → editions(id),
                            is_active bool, sort_order int, audit
                            -- is_free = (monthly_price is null and annual_price is null) → domain'de computed

edition_features            id, edition_id → editions(id) ON DELETE CASCADE, feature_name varchar(128),
                            value varchar(2000), UQ(edition_id, feature_name)

tenant_features             id, tenant_id → tenants(id) ON DELETE CASCADE, feature_name varchar(128),
                            value varchar(2000), UQ(tenant_id, feature_name)   -- host override

subscriptions               id, tenant_id → tenants(id) UQ (tenant başına tek aktif abonelik),
                            edition_id → editions(id), status varchar(24),
                            billing_period varchar(16) NULL,           -- MONTHLY | ANNUAL | null(free)
                            price_amount numeric(19,4) NULL, price_currency varchar(3) NULL,  -- SNAPSHOT
                            trial_end_at timestamptz NULL, current_period_end_at timestamptz NULL,
                            grace_end_at timestamptz NULL, cancelled_at timestamptz NULL,
                            external_ref varchar(128) NULL, provider varchar(32) NULL,
                            legacy_edition_id int NULL, legacy_tenant_payment_ref varchar(128) NULL,  -- F6/ETL
                            audit
                            ix(status, current_period_end_at)

subscription_events         id, subscription_id → subscriptions(id) ON DELETE CASCADE,
                            from_status, to_status, reason varchar(64), occurred_at, actor varchar(64)
                            -- denetlenebilir yaşam döngüsü izi (audit modülünden bağımsız, domain kaydı)

payments            (C)     id, tenant_id, subscription_id, edition_id, amount numeric(19,4), currency,
                            billing_period, status varchar(16), provider varchar(32),
                            external_payment_id varchar(128), is_proration bool, invoice_id NULL,
                            audit, UQ(provider, external_payment_id)

invoices            (C)     id, tenant_id, subscription_id, payment_id → payments(id),
                            invoice_no varchar(32) UQ, invoice_date, amount numeric(19,4), currency,
                            legal_name, address, tax_no, audit

webhook_events      (C)     id, provider varchar(32), event_id varchar(128), event_type varchar(64),
                            payload_hash varchar(64), status varchar(16), attempts int,
                            received_at, processed_at NULL, last_error varchar(2000),
                            UQ(provider, event_id)    ← idempotency anahtarı
```

**Kaynaktan ayrılan kararlar:** tutar/edition **ilişkisel** (JSON değil); `price_*` abonelikte **snapshot** (edition fiyatı
sonradan değişse mevcut abone etkilenmez → K13 çözümü); `status` **explicit**; `legacy_*` kolonları F6 izlenebilirliği için.

## 3. Subscription state machine (explicit)

```
enum SubscriptionStatus { TRIALING, ACTIVE, GRACE, EXPIRED, CANCELLED, PENDING_PAYMENT }
```

| # | Kaynak | Tetikleyici | Hedef | Yan etki |
|---|---|---|---|---|
| S1 | — | Tenant oluşturuldu, free edition | `ACTIVE` | `current_period_end_at = null` (süresiz) |
| S2 | — | Trial ile atama (`trial_day_count > 0`, edition ücretli) | `TRIALING` | `trial_end_at = now + trialDays` |
| S3 | — | Ücretli atama, ödeme bekleniyor | `PENDING_PAYMENT` | tenant erişimi kapalı (kapı §6) |
| S4 | `PENDING_PAYMENT` | Ödeme onaylandı (**server-side**) | `ACTIVE` | `current_period_end_at = now + period` |
| S5 | `TRIALING` | Ödeme onaylandı | `ACTIVE` | trial kalanı **devredilmez** (kaynakla aynı) |
| S6 | `TRIALING` | `trial_end_at` geçti | `EXPIRED` | **grace YOK** (kaynaktaki asimetri düzeltildi: trial'da grace uygulanmaz, tutarlı) |
| S7 | `ACTIVE` | `current_period_end_at` geçti, `grace_day_count > 0` | `GRACE` | `grace_end_at = end + graceDays` |
| S8 | `ACTIVE` | `current_period_end_at` geçti, grace yok | `EXPIRED` | |
| S9 | `GRACE` | `grace_end_at` geçti | `EXPIRED` | |
| S10 | `EXPIRED` | `expiring_edition_id` tanımlı (free) | `ACTIVE` (yeni edition) | downgrade; `current_period_end_at = null` |
| S11 | `ACTIVE`/`TRIALING` | Yenileme ödemesi (recurring) | `ACTIVE` | `current_period_end_at += period` |
| S12 | herhangi | Host/tenant iptali | `CANCELLED` | dönem sonuna kadar erişim (`current_period_end_at` korunur) |
| S13 | `ACTIVE` | Edition değişimi (upgrade/downgrade) | `ACTIVE` | proration; **dönem sonu kaymaz** (kaynakla aynı) |

**Kurallar:**
- Geçersiz geçiş → `DomainException(VALIDATION)` **fırlatılır** (kaynaktaki sessiz no-op taşınmaz → K11).
- Her geçiş `subscription_events`'e yazılır (from/to/reason/actor).
- `EXPIRED`/`PENDING_PAYMENT` → tenant iş uçlarına erişemez (§6); `CANCELLED` dönem sonuna kadar erişebilir.
- Free edition trial alamaz; `expiring_edition_id` hedefi **free olmak zorunda** (kaynak kuralı korunur).
- Ay hesabı `java.time.Period.ofMonths(...)` ile; ay-sonu clamp (31 Oca + 1 ay = 28/29 Şub) testli (F5-R5).

## 4. Billing abstraction (SPI) — kaynakta olmayan katman

```java
public interface BillingProvider {
    String key();                                             // "manual" | "stripe" | ...
    boolean supportsRecurring();
    CheckoutSession createCheckout(CheckoutRequest request);   // → redirect URL + external ref
    PaymentStatus fetchStatus(String externalPaymentId);       // reconciliation için
    void cancelSubscription(String externalSubscriptionId);
}
```
- Spring `List<BillingProvider>` injection → `BillingProviderRegistry` (`key()` ile map). Yeni sağlayıcı = **tek sınıf**
  (kaynaktaki 7 katmanlı elle iş ortadan kalkar → G13).
- **Slice A:** yalnız `ManualBillingProvider` (host admin ödemeyi manuel onaylar; gerçek gateway yok).
- **Slice C:** `StripeBillingProvider` — **Prices API** (legacy Plans değil), `metadata.tenantId` + `metadata.subscriptionId`
  (`Customer.Description` taşınmaz → K3).
- Tutarlar `BigDecimal` + `currency` (F5-R4).

### 4.1 Server-authoritative aktivasyon (K1 çözümü)
Abonelik aktivasyonu **yalnız sunucu tarafında** olur:
1. `webhook` (birincil) veya 2. `reconciliation job` (yedek, `PENDING_PAYMENT`/`Paid`-takılı kayıtları sağlayıcıdan `fetchStatus` ile doğrular).
İstemcinin "başarılı döndüm" çağrısı **hiçbir durum değiştirmez**; yalnız UI yönlendirmesi içindir.

## 5. Webhook idempotency stratejisi (K2 çözümü)

```
1. İmza doğrula (sağlayıcıya özel; secret yalnız env). Geçersiz → 400 (retry anlamlı değil, ama log+alarm).
2. INSERT INTO webhook_events(provider, event_id, ...) ON CONFLICT (provider, event_id) DO NOTHING
   → 0 satır  ⇒ DUPLICATE: hiçbir iş yapma, 200 OK dön.
   → 1 satır  ⇒ yeni event, işlemeye devam.
3. İş mantığı ayrı transaction'da; başarı → status=PROCESSED, processed_at=now.
4. Hata:
   - Geçici (DB/ağ)        → status=RETRYABLE, 5xx dön (sağlayıcı yeniden dener)
   - Kalıcı (bilinmeyen tip, parse) → status=DEAD, last_error kaydet, **200 OK dön** (sonsuz retry döngüsü YASAK)
5. Bilinmeyen event tipi → kaydet + 200 (sessizce yut, alarm sayacı).
```
**Kaynaktaki hata bilinçli olarak taşınmaz:** duplicate/kalıcı hatada `400` dönmek Stripe'ı sonsuz retry'a sokuyordu.
Recurring yenileme yolunda da aynı idempotency uygulanır (kaynakta hiç guard yoktu → çift uzatma).
`webhook_events` ayrıca **manuel replay** için kaynak (DEAD kayıtlar admin ekranından yeniden işlenebilir — Slice C).

## 6. Feature gating

**Çözümleme zinciri:** `tenant_features` (host override) → `edition_features` (tenant'ın edition'ı) → `FeatureDefinition.defaultValue`.

- Registry: `FeatureDefinitions` — `SettingDefinitions` deseninin birebir kopyası (statik liste, `byName`, bilinmeyen ad → validation hatası). **Tablo paylaşılmaz** (settings ≠ features; §Gap G2-G5).
- `FeatureDefinition(name, displayNameKey, type{BOOLEAN,NUMBER,STRING}, defaultValue, visibleOnPricingTable)`.
- Enforcement (Slice B): `@RequiresFeature("app.chat")` + AOP interceptor → kapalıysa `DomainException(FORBIDDEN)`;
  sayısal limitler için programatik `featureChecker.intValue("app.maxUserCount")` (0 = sınırsız, kaynakla aynı semantik).
  **Kaynakta `[RequiresFeature]` hiç kullanılmıyordu — burada gerçek deklaratif kapı kuruluyor.**
- Cache: Redis, anahtar `feature:{tenantId}:{name}`; edition/tenant feature yazımında ve edition ataması değişiminde **evict** (F5-R2).
- **Yazma yetkisi yalnız host** (`Side.HOST`) — tenant kendi limitini yükseltemez (F5-R3).

## 7. Tenant provisioning / paket atama akışı

```
[Host admin] POST /api/tenants                → tenancy modülü tenant yaratır (mevcut)
                                                └─ event: TenantCreated(tenantId)
[saas @ApplicationModuleListener]             → varsayılan edition ile Subscription oluştur
                                                 (free → ACTIVE, trial → TRIALING, ücretli → PENDING_PAYMENT)
[Host admin] PUT /api/subscriptions/{tenantId}/edition   → paket atama/değiştirme (proration Slice B)
[Host admin] POST /api/subscriptions/{tenantId}/activate|cancel|extend
```
- **Atomiklik:** abonelik oluşturma tek transaction (kaynaktaki 2-UOW parçalanması taşınmaz).
- Event tabanlı kurulum sayesinde `tenancy → saas` bağımlılığı **oluşmaz** (F5-R1).
- Seed: `default` tenant için varsayılan edition — **ayrı idempotent adım** (host-admin kontrolüne bağlanmaz, F5-R6).

### 7.1 Abonelik geçerlilik kapısı
`TenantResolverFilter` zaten "tenant aktif mi" kapısını içeriyor. Buna **`SubscriptionGuard.isTenantSubscriptionValid()`**
eklenir (cache'li): `EXPIRED`/`PENDING_PAYMENT` → `403 SUBSCRIPTION_INVALID`. Muaf uçlar: auth, abonelik/ödeme ekranları,
host uçları (F5-R7).

## 9. Gözlemlenebilirlik ve denetim

- `subscription_events` → domain düzeyi yaşam döngüsü izi (audit modülünden bağımsız, sorgulanabilir).
- `Subscription` ve `Edition` `@TrackChanges` listesine eklenir (mevcut entity-history altyapısı).
- Metrikler (Micrometer): `saas.subscription.active`, `.trialing`, `.expired`, `webhook.events{status}`, `payment.failed`.
- Webhook DEAD kayıtları için alarm sayacı.

| # | Karar | Gerekçe |
|---|---|---|
| ADR-0009 | Explicit `SubscriptionStatus` + domain geçiş metotları | Kaynaktaki implicit 3-alan kombinasyonu ambiguous (K8) |
| ADR-0010 | `BillingProvider` SPI + registry; Slice A'da yalnız manual | Kaynakta ortak arayüz yok (G13); gerçek gateway riski ikinci slice'a ertelenir |

| ADR-0014 | Server-authoritative aktivasyon (webhook + reconciliation), istemci çağrısı durum değiştirmez | Ödeme alınıp edition yükselmeme riski (K1) |
